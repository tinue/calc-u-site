Chapter 8 · Settings

Settings

Settings are your preferences for a product: the model it starts with, the startup preset of each model, the folders it uses. They never say which modules, peripherals or media a machine has; a preset does that (Presets).

The Settings dialog

File ▸ Settings… opens the dialog (More ▸ Settings… on every bar, the only way on mobile; on macOS it is in the application menu). A change applies at once and is kept; where the settings file cannot be written, a notice says so and the change holds until you quit. The only button is Close (Done on iOS). The dialog can be used while an operation runs. Its sections, each shown when the frontend has one of its settings:

Section Settings
General Startup model: "Last used" or one of the product's models
Startup presets one row per model: "None", the bundled startup presets for that model, or a file chosen with "Choose…" (checked before it is set)
Storage the save folder, and the product's further folders
Folders the folder in which each file dialog starts
Tracing the trace folder and the largest trace file, in MB
the product's sections the product's own settings (Settings of this product)
App log how much the app log keeps (The app log)

A folder's row shows the folder in use, with ~ for your home folder, a "Change…" button, and "Reset", which puts the setting back to its default.

The settings file

All settings are kept in one text file, <Product>.ini, named after the product as it is written. It is written when the product first starts, with every key at its default (a model's startup preset at the bundled one, where the product names it) and a comment line above each key, and again whenever a setting changes. It is read when the product starts, and not again while it runs: to edit it by hand, quit the product first.

Platform Where the settings file lies
macOS, iOS the product's Application Support folder (~/Library/Application Support/<Product>/, or inside the app's container when it is sandboxed)
Windows %APPDATA%\<Product>\
Linux $XDG_CONFIG_HOME/<Product>/, or ~/.config/<Product>/ when that variable is not set
Web the browser's storage for the page

No other place is searched. The rules of the file are in the reference.

  • A key that is missing has its default.
  • A value its key does not accept counts as missing, so the setting has its default; the value stays in the file until you change the setting.
  • Keys and sections the product does not know, comments, blank lines and the order of the file are kept when the product writes it.
  • A file that cannot be read is left untouched; the product starts with the defaults and says so in its app log.
  • A file without its format-version line is not read; the product starts with the defaults and says so.
  • When two copies of the product run, the last one to write wins.

The family's keys

These are the family's keys, with their meanings and defaults; the product's part of this chapter lists which of them the product has. A key a frontend has no use for is kept in the file and ignored. Keys marked "written by the product" are kept up to date by the product itself.

Key Default Meaning
[startup] model last The startup model: last (the model used last) or a model's name. A value that is neither counts as last
[startup] last-model empty The model used last; written by the product. A model built by a preset counts too. If it names no model of the product, the product's fallback model starts
[preset] <model> empty; at the first start the model's bundled startup preset, where the product has one One key per model, named after the model: the startup preset of that model, a path or a bundled preset. Empty: none, so the model is built as the product's built-in default machine
[storage] save-folder empty The save folder, where instances, screenshots, traces and serial links go. Empty: a folder named after the product in your home folder (desktop frontends)
[storage] cassette-folder empty The folder for cassettes. Empty: Cassettes in the save folder
[trace] folder empty The folder for traces. Empty: the save folder
[trace] max-file-size-mb 50 The largest trace file, in MB (MiB: 1 MB is 1 048 576 bytes); zero or less counts as 50; read when a trace starts (Debugger)
[trace] location app-support Where traces go in the frontends that offer the choice: app-support or icloud
[app-log] level default How much the app log keeps: default (warn; info in a development build), error, warn, info or debug; applied at once (The app log)
[serial] link-folder empty The folder for the files of serial links. Empty: the save folder
[folders] <kind> empty One key per kind of file the product opens: the folder its file dialog starts in. Written by the product: the folder last used, or fixed:<folder> for a folder set in the Settings dialog, which later picks do not change
[window] <key> the product's The place and size of the main window and the split between its panels, as plain numbers; written by the product
[window] paper-own-window false The paper in a window of its own, true or false; written by the product (The paper in its own window)
[window] paper-x, [window] paper-y, [window] paper-width, [window] paper-height empty, empty, 400, 640 That window's left and top edge and its size, as plain numbers; written by the product

Which models stand for <model>, which kinds for <kind> and which names for <key>, and the product's own keys, are in the product's part: Settings of this product.

The app log

The app log tells how the product ran: when it started, what went wrong and why, and, at the levels below, what it did for you. It is not the log of the debugger, which tells what the calculator ran. Each line has the date and time and one of the levels:

Level What it keeps
error the product, or the machine's session, ended or could not start, with everything needed to find out why
warn something failed and the product went on: a copy to the clipboard, a file that could not be written, a setting that could not be saved, each with its cause
info also what the product did for you: started, saved, imported, opened
debug also the product's own detail

A level keeps its lines and those above it in the table. The setting [app-log] level (the Settings dialog's "App log level") chooses it; default is warn. On a desktop frontend, --app-log-level <level> on the command line sets the level for one run; on the Web, ?app-log-level=<level> at the end of the page's address does.

Help ▸ Show App Log shows it (also in More):

Platform Where the app log lies
macOS ~/Library/Logs/<Product>/<Product>.log; Show App Log opens it in Console
Windows %LOCALAPPDATA%\<Product>\<Product>.log
Linux $XDG_STATE_HOME/<Product>/<Product>.log, or ~/.local/state/<Product>/<Product>.log
iOS inside the app; Show App Log offers it to share
Web the browser's console; Show App Log downloads the last 2000 lines as <Product>.log

A file over 1 MiB is kept as <Product>.1.log when the product starts, and a new one begun. When you report a problem, add the app log.

Folders

  • A folder that does not exist yet is created when something is first written there.
  • A save folder that cannot be created or written is reported, and nothing is written to another folder instead.
  • A path is absolute; a leading ~ stands for your home folder.
  • In a frontend that keeps files in iCloud, the save folder is its iCloud Documents folder, or its local Documents folder when iCloud is not available; media are not moved between the two.
  • In a Web frontend the save folder lies in the browser's storage for the page; screenshots and traces are offered as downloads instead.
