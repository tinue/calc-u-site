Loading a preset

Presets are plain UTF-8 text files with named sections. You can include only the sections you need.

New to writing a preset from scratch? The tutorial builds one up section by section, with a downloadable file at every step.

Preset tutorial →
# 800 steps, 20 data registers (R00–R19) — "2 OP 17"
PARTITION: 799.19
# Magnetic card with one Label
CUECARD:
Template: MagnetCard
Title: Example
Banks: 1,2
A: Start
# Load the Master Library
SOLID-STATE-MODULE: ML
# Force Printer On
PRINTER: on
# Program Listing
PROGRAM:
000  76  LBL
001  11  A
002  89  π
003  95  =
004  91  R/S
# Data Registers
REGISTERS:
00 = 3.141592653589793   # π  (verify RCL 00 → 3.141592654)
# Type some keys after load / reset
KEYSTROKES:
84   3
11   A
Wait: 2s
43   RCL
92   0
92   0

PARTITION: sets the step split between program memory and data registers.

PROGRAM: accepts sparse step listings, numeric keycodes, and the ... gap marker.

REGISTERS: stores calculator variables as decimal numbers.

KEYSTROKES: injects matrix codes after the file loads. Between keys, lines such as Wait:, FullSpeed: and RegularSpeed: control timing, and a few more (Trace:, ZeroElapseTime:, ReportElapseTime:) help with timing and debugging programs. To run a long program at full speed, put FullSpeed: before the key that starts it; Wait: pauses so you can see what the calculator shows. An unknown directive, or a Wait: without a unit, is reported as an error rather than read as keys.

CUECARD: defines the on-screen cue card that appears with the loaded file or module.

SOLID-STATE-MODULE: and PRINTER: let a file select the matching module and printer state automatically, and MODEL: switches to the calculator the file is for.

A KEYSTROKES: script can also work the controls around the calculator: PrinterTrace: on / off sets the printer's TRACE switch, CutPaper: cuts the paper, and DebugPanel:, Freeze:, FreezeOnStart:, Step: and Resume: do what the debugger's tabs and buttons do. While the debugger is frozen, the script's keys wait until it runs again. Older presets using SKIP-RESET: or key 99 now get an error; a reload in the same file and PrinterTrace: replace them.

This page covers enough to load and tweak existing files. The complete grammar — matrix code table, 2nd-function presses, the CUECARD field list, and the math-notation shorthand used in cue cards — is developer documentation kept in the GitHub repository: reference/StateFileFormat.md →

A whole session in one preset

Some programs don't fit one load. Their users changed a few steps between runs, or fed the calculator one magnetic card after another. A preset can do both, so one file plays the whole session.

Keyed-in changes. A PROGRAM:, REGISTERS: or CUECARD: section after KEYSTROKES: is applied once the program has stopped, as if you had typed the changes in. Only the steps and registers it lists change; everything else stays. This works on every model.

PROGRAM:
…                    # the program, loaded as usual
KEYSTROKES:
11                   # A: it runs and stops
PROGRAM:
017 01               # then step 017 changes …
REGISTERS:
05 = 2.5             # … and register 05
KEYSTROKES:
11                   # A: run again

A stack of cards (TI-59). For larger changes, TI-59 owners prepared their cards in advance and fed them in a written-down order. Some programs stop and show which card comes next. Others ask for a card themselves (Write or INV Write in the program) and simply wait for it. A preset feeds both kinds:

  • InsertCard: pushes a card into the stopped calculator, as you would by hand.
  • ArmCard: lays a card ready; it goes in as soon as the program asks for one.
  • A card file's side goes after the name: InsertCard: Results:2. Without one, it is side 1.
  • A card is a file in your card folder, by its name, or a temporary card named mem:something that lives only while the preset is loaded. A CARD: block defines such a card's registers and steps in the preset itself. A card replaces its whole bank, as a real one does.

Picking the right card is up to the preset, just as it was up to the user.

CARD: mem:Bank4      # a card defined right here
Bank: 4
REGISTERS:
00 = 12
01 = 3.5
END-CARD

KEYSTROKES:
InsertCard: mem:Bank4   # push it in, as at the start of a session
ArmCard: Results        # ready for the program's own Write
11                      # A: run

Labeling the A–E and A′–E′ keys

The five plain keys (A–E) and their 2nd-function row (A′–E′) are exactly what real TI-59/58/58C cards label. A CUECARD: section can do the same thing on-screen — either as its own row of short per-key labels, or as one line of running text across the whole row.

Template picks the card artwork and layout, and matches the real card it stands in for — MagnetCard and CueCard look almost identical on screen, since both were the same front-side label design. The difference is on the back: a real magnetic card has a magnetic coating that stores the program; a cue card doesn't. Use MagnetCard if the preset is meant to end up written onto a magnetic card (it also shows the Banks page badges; once written to a card file, the corners show the bank each side really holds). Cue cards shipped for TI-58, TI-58C and TI-59 owners, but TI-59 owners tended to skip them and just label whichever magnetic card already held the program instead; TI-58 and TI-58C, having no card reader at all, relied on cue cards since there was no magnetic card to label in the first place — use CueCard for that case, or for any file that just wants an on-screen label without a magnetic-card connotation. Which of the two you pick for a given preset is mostly personal preference, except when the file is a step toward an actual magnetic card — then use MagnetCard to match. SolidStateCard reproduces the pre-printed cards that shipped with a Solid State Software module; real ones can't be edited by the module's user, and in the emulator they're normally only touched by the project's developer to document a built-in module — reach for it yourself only if you're prototyping your own module (it shows an ID like ML-01 instead of Banks).

Set fields A through E for the plain-key row, and A′ through E′ for the 2nd-function row, as in the example below. Row1 and Row2 put one line of running text across a row instead. The example also shows \blank, which lets a label span the next key position, and shortcuts such as \sqrt for the symbols real cards use. All the fields, their alignment and ink options and the symbol table are in reference/StateFileFormat.md.

CUECARD:
Template: MagnetCard
Title: Roots & Powers
Banks: 1, 2
A: \sqrt x
B: x^{2}
C: 1/x
D: x \to y
E: \blank
A': \sum x_{i}
B': \xbar
C': n
D': \blank
E': \blank

Loading a labeled card

From a preset — tap Preset and pick a .ti59/.ti58/.ti58c file with a CUECARD section; it's applied immediately and stays until you load something else or reset.

Onto a virtual magnetic card — a card written by a preset gets that preset's CUECARD, with its full layout, in the card file along with the program or data. A fresh card from the Crd button starts with its file name as the title; edit the card file to add more. Fitting a card restores the label; pressing a corner reads the contents.

By editing the card file directly — virtual card files are plain text too (see the FAQ entry on where they live), with the same CUECARD: syntax as a preset. Add or edit that section in a text editor and the label shows the next time the card is fitted.
