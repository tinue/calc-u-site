This page explains the emulator controls as they behave in the app: the calculator, the printer, the debug pane, and the settings that affect a session.

The calculator

The calculator view is the main working surface. On iPhone and on iPad in portrait, it uses the same key layout as the app screenshot; on iPad in landscape, the layout mirrors the Mac view.

The top display area shows the current number and status indicators, the cue card area directly beneath it shows module/context notes, and the keyboard area contains the full key matrix for normal operation.

Bottom bar on iPhone and iPad (left to right): Reset (long press: a clean reset that also wipes the memory), the model picker (TI-59/TI-58/TI-58C), the two Crd buttons (load a card; insert a blank card to write) and Eject Card — on the TI-59 only, the one with a card reader — then Preset and Settings.

On the Mac, Windows and Linux, the bar has the same buttons except Settings, which is in the app menu (Mac) or the File menu (Windows, Linux). Holding ⌘ (Mac) or Ctrl (Windows, Linux) turns Reset into Clean. On the Mac the model picker sits in the window's toolbar.

The printer

The printer view has a PC-100C button at the top (connects or disconnects the printer, and resets the calculator), a dot/text toggle, the printer's PRINT and ADV keys, and T, its TRACE switch. Copy puts the paper strip on the clipboard as an image and as text; cut copies it and then clears the paper.

The text view is useful when you want to read or copy output quickly. The dot view is the closer match to the physical printer.

The debug pane

The debug pane has three tabs: CALCULATOR, CPU, and LOG.

  • CALCULATOR — Program listing (from RAM) centred on the next instruction to execute, with live registers and flags.
  • CPU — Execution trace of ROM instructions that already ran. State shown is after each instruction. Scrollable history, one-opcode step.
  • LOG — Dumps of the SCOM registers, memory, program and variables, the debug log level, and the TRACE toggle. Use TRACE to capture a binary session file for detailed analysis with read_trace.py.

The CALCULATOR and CPU tabs have different step semantics: CALCULATOR advances one program step, as SST does; CPU advances exactly one ROM opcode. See Using the debugger.

Settings

Settings choose the Startup Calculator (a model, or Last Used), the Solid State Module, the LED Segment Style (Modernized or Classic), and the trace file's Maximum File Size, so long debug sessions don't grow without bound. iPhone and iPad add Keyboard Feedback and Debug Page in Portrait.

Where files go: on the Mac, the trace file's Save Location (local, iCloud or a folder you choose); on iPhone and iPad, traces go to the app's iCloud folder. On Windows and Linux, Files sets the preset, card and trace folders.
